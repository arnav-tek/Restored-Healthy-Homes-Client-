## Findings, ordered by severity

### 1. P1 — Native form submission puts private intake fields in the URL

- Location: `src/features/consultations/connected-request.tsx:172`, submit control at line 227.
- The form relies solely on `onSubmit`; it has no method/action fallback or hydration readiness guard. Its submit button is enabled in server-rendered HTML whenever categories exist.
- Reproduced against the actual connected preview with a fresh JavaScript-disabled browser context and synthetic fields. Clicking **Send request** navigated by GET to `/consultations` with query keys `name`, `email`, `categoryId`, `format`, `topic`. No consultation API write occurred. The same native fallback is available before hydration or when scripts fail.
- Impact: visitor contact details and potentially sensitive topic text enter browser history/address-bar URLs and may enter URL-based infrastructure telemetry. This also fails to save the request. The page's no-referrer header does not remove information already in the URL/history. No claim is made that real visitor information was leaked during this synthetic test.
- Smallest correction: disable the fieldset/submit until hydration, provide a no-script explanation, and set an explicit safe fallback that cannot serialize intake into a GET URL. Follow the existing readiness pattern in `ProfileFieldsEditor`. A method attribute alone does not implement a working non-JavaScript submission path. Add a no-script/pre-hydration regression.

### 2. P2 — Connected members cannot opt into or out of free-phone participation

- Locations: `src/features/member/connected-profile.tsx:130`; `src/validation/member-account.ts:16`; default at `supabase/migrations/20261107231103_database_foundation.sql:50`; required eligibility predicate at `supabase/migrations/20261114191924_connected_consultations.sql:56`.
- The participation checkbox is implemented only by `src/features/member/showcase-preferences.tsx:36`, which dispatches to demo React state. The connected editor has no participation control; its mutation allowlist rejects an additional participation field. The connected profile creation/update SQL omits the column. Hosted routine inspection found only the public-directory reader and consultation candidate/target readers referencing `free_phone_consultation`, with no connected setter.
- Reproduction: inspect a connected profile's editor/save contract; a newly created professional gets `free_phone_consultation=false`, and the member has no permitted operation to change it. Assignment correctly rejects such a listing even after all other eligibility conditions are satisfied.
- Impact: new members cannot join the consultation pool without an operator write, and an operator-opted-in member cannot withdraw participation through the connected application. This is a missing client-requested workflow, not a reason to relax eligibility. Staging currently has zero professional listings, so no live member preference change was attempted.
- Smallest correction: add an owner-authorized, version-checked connected preference editor and narrow RPC/update contract. Preserve approval, membership, suspension and independent certification states. Test that opt-out immediately blocks subsequent assignment/acceptance.

### 3. P2 — Workspace pagination retains the previous page's state

- Locations: `src/features/consultations/connected-workspace.tsx:9`, pagination links at line 24; parent `src/features/consultations/connected-pages.tsx:52`.
- `useState(initial)` captures only the first server result. Query navigation uses Next links on the same page, while the parent supplies new `initial` data without changing the workspace key. There is no synchronization with new props. Refresh also requests the stale `data.page`.
- Reproduced with the actual workspace component bundled into an isolated React harness: rendered page 1, then rerendered the same component with page 2 records. Page 1 topic/indicator remained; page 2 topic count was zero. Only Next Link was replaced with an anchor shim. This is component verification, not a live authenticated Next pagination walkthrough.
- Impact: queues over 20 requests can appear stuck on the first visited page; the refresh button reloads that old page despite the changed route.
- Smallest correction: explicitly manage page changes, or key the workspace by the validated requested page at the server boundary. Account for unsaved notes before remounting; do not silently discard drafts. Add a query-navigation regression using more than 20 disposable records.
