# Supabase database foundation — 2026-11-08

Applied through the user's signed-in Supabase SQL Editor to **restored-healthy-homes-staging**, project `xjecnuebalmmblowmtks`. Before execution, the database contained only auth/realtime/storage/vault system tables. No existing application data was replaced.

## Implemented

The new `rhh` schema contains 15 tables: categories, accounts, professionals, applications, memberships, professional_categories, services, credentials, inquiries, questions, answers, reviews, consultations, certification_pathways and articles. The migration includes foreign keys, supporting indexes, length/status/rating constraints and conservative defaults: pending applications, inactive membership, unverified credentials, unpublished content. Public profile fields are separated from application contacts, decisions and billing references. Consultation formats/statuses follow the current free-phone prototype; no consultation charge is introduced.

Only the eight approved category IDs, names, base monthly USD amounts and billing keys are seeded. Renames preserve associations. No combined-category total or featured price is invented. No fictional users, reviews or other workflow records were inserted in Supabase. No Auth accounts or admin permissions were created.

All tables have enabled and forced RLS; schema/table/function grants are denied to PUBLIC, anon and authenticated. There are deliberately **no browser CRUD policies yet**. This is a closed database foundation, not a completed member authorization system. The private eligibility function preserves approved + active + unsuspended, including null rejection; future public queries must actually apply it.
