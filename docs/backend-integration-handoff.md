- The trigger snapshots the accepted inquiry's original recipient and confirmed **Auth email**, never its sender address or editable public contact. Immediately before a provider call, routing checks the snapshot, current listing owner, protected member role, email confirmation, email equality and account availability. Email/owner/role changes, deletion or a ban cancel the notification without rerouting it. The original member retains B1 inbox history. Listing eligibility at submission is unchanged; later membership/suspension changes do not erase accepted inquiries.

Abandoned work is reclaimed; stale workers cannot prepare or finish a new lease. Safe temporary failures retry with exponential backoff/jitter and bounded Retry-After. Metadata snapshots the original owner as well as the listing: transfer does not give a new owner access to old private uploads or silently publish them. Ownership transfer/media reconciliation requires a separately reviewed operator procedure.
- Public display requires **explicit image publication + current association + unchanged owner + approved application + active membership + no suspension**. Public DTOs add only `photoId`; no bucket paths, owner IDs, credentials or private fields are serialized. `/api/public/profile-image/[professionalId]/[photoId]` uses an anonymous public routing RPC on every request before the server reads bytes. Owner previews use authenticated `/api/member/profile-media?image=<uuid>`. Both return private/no-store responses and neutral unavailable states; binary responses preserve refreshed cookies. No public/signed/upload URLs or Next image-optimizer caching are used. [Supabase documents that public bucket URLs bypass read authorization and signed URLs have independent expiry](https://supabase.com/docs/guides/storage/serving/downloads); routing through the server permits immediate denial of **new requests** after removal/hiding. Previously downloaded copies cannot be recalled; a request already in flight may finish.
- Selecting a file only creates a revocable local preview. **Save profile image** uploads a private draft, then associates it using a separate version check and explicit publication choice. New selections default to unpublished. Text/profile saving is independent and does not clear image drafts. Failed uploads/associations leave the saved pointer unchanged; drafts survive reported association failures, retries reuse their reserved ID, and unused uploaded drafts can be selected/discarded after reload. Removal is staged until saved; cancel does not erase the saved image. Stale versions return 409 rather than silently overwriting another save.
- Input: JPEG/PNG/WebP only, **5 MiB**, **16 million pixels**, static single-page images. Server Sharp **0.35.5** (already bundled transitively; now pinned directly) decodes/re-encodes WebP, autorotates, resizes within 1200x1200 and strips EXIF/ICC/unneeded metadata. Disguised, malformed, truncated, animated/unsupported and oversized input is rejected. Streaming body reads cap size and have a 30-second deadline; image processing is bounded to 15 seconds; Storage calls time out after 15 seconds. `upsert=false`: saved objects are never overwritten in place.
- Quotas serialize on the owned listing: at most **four retained reservations/objects** and **20 reservations per UTC day**. Invalid processed uploads consume an attempt and remain bounded. Canceled/replaced objects become private cleanup records only after the saved association changes. Cleanup is owner-authorized, uses Storage API deletion, verifies absence before dropping metadata, and cannot delete a current object. A **ten-minute safety grace** protects in-flight uploads; unused drafts expire after **24 hours**. Cleanup retries on subsequent image/account requests; no cleanup scheduler or guaranteed deletion deadline is active. Without a later visit, private abandoned objects may remain, bounded by the retained-file quota. Grace-period objects continue consuming quota. Storage or cleanup failure never removes the currently associated image. Existing inquiry queue/retry safeguards are unchanged.

### Decisions, re-review and privacy

| Current review state | Permitted transition |
| --- | --- |
| Pending | Publish or reject. |
| Published | Hide or reject. |
| Hidden | Restore to pending, or reject. |
| Rejected | Restore to pending. |
