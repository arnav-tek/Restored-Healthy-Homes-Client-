## Corrections

1. **Private intake URL fallback.** `ConnectedConsultationRequest` uses the existing `useDemoReady` server-false/client-ready guard. The fieldset and submit are disabled until ready; the handler also checks readiness/busy state. A visible no-script explanation states that JavaScript is required. The native fallback is explicitly POST `/api/consultations`, whose existing JSON-only handler rejects URL-encoded submission. There is no supported non-JavaScript save path. JSON validation, retry UUID/token reuse, failed-save drafts and receipt/status flow remain. Cancellation still submits the displayed request ID and version; the server compares the ID to the authorized shared cookie before invoking the RPC.
2. **Connected participation.** The existing connected profile now includes “Offer free phone consultations,” with database loading, explicit save, busy state and success/error recovery. `/api/member/consultation-preference` uses the existing Auth/cookie/private-cache/origin/bounded-body conventions. Exact boolean/version input is allowlisted; saved output is limited to enabled/version plus the save acknowledgment. The private RPC derives the listing from the current confirmed member, locks the protected account then owned profile, checks the same `profile_version` used by ordinary profile/location edits, and updates only participation plus that version. It does not accept owner IDs, role, approval, membership, suspension or credential decisions. Failed/stale saves retain the selected value. A comparison link and explicit “Reload saved version, keep participation choice” action load the saved value/version for comparison without replacing the choice. Other profile/location forms become stale after a preference save and must reload their shared version; no location logic changed.
3. **Pagination and private drafts.** New validated server page props synchronously select the rendered data/page; refresh captures that page and source identity and rejects late/superseded results. The workspace is keyed by protected identity and admin/member scope, **not page**. A page-load error leaves the same identity-scoped workspace mounted so drafts are not silently lost. Drafts stay only in React memory, indexed by request ID and separately bound to the note/assignment's original saved version. Paging/Back/Forward does not move them to another record. A saved-data refresh does not silently upgrade a draft's version: saved values are displayed for comparison, followed by an explicit “Use current saved version, keep draft” action. Successful saves clear only the matching submitted field/version; they cannot erase a newer edit from a remounted card. Logout/account change follows the existing SessionBoundary and identity-key reset. No private drafts enter URLs or browser storage.

Opt-out immediately fails the existing target eligibility checks for assignment/acceptance, while an already assigned request can still be declined under the existing rules. Opt-in never changes approval, active membership, suspension or category eligibility. Existing request/event history is untouched.
